# Project context

## Module map


| Directory | What it is |
|---|---|
| `dikonekti/` | Flutter app (mobile). Contains a Flutter `web/` target that is not used for the web dashboard. |
| `Dikonekt_Backend/dikonekti/` | Django REST API (`accounts`, `alerts`, `appointments`, `messaging`). |
| `dikonekti-web/` | Next.js doctor dashboard (DIK-001). Named `dikonekti-web` so it cannot be confused with Flutter's `dikonekti/web/`. |

## Backend: doctor verification (DIK-003)

- Roles are `doctor`, `disabled` and `admin`. `DoctorVerification` (in `accounts/models.py`) holds a doctor's status and does all status changes (`submit`, `approve`, `reject`), each under a row lock. Views only call it.
- Permissions are in `accounts/permissions.py`: `IsAdmin`, `IsVerifiedDoctor` (answers `403` with `code: "verification_required"`), `IsDisabledOrVerifiedDoctor` (shared list endpoints). Route alerts, appointments and messages through `User.approved_registered_doctor`, never `registered_doctor`.
- File rules (type check from the first bytes, 5 MB, private storage, delete after commit) are all in `accounts/files.py`. Certificates are stored in `DJANGO_MEDIA_ROOT` (required unless debug; checked at start-up by `accounts.E003`).
- Create an admin with `python manage.py create_admin <username>`.

## Web: doctor verification (DIK-004)

- `decideRoute` (`dikonekti-web/src/lib/route-gate.ts`) returns `verification` for a doctor whose `verification_status` is not `approved` (unknown or missing counts as not approved). The home page and `/verification` redirect each other's visitors.
- The proxy (`src/app/api/[...path]/route.ts`) reads bodies as bytes with a 6 MB cap (`src/lib/read-body.ts`); `apiFetch` sends `FormData` unchanged and redirects on `403 verification_required`.
- `LogoutButton`, `ErrorBanner` and `ProfileLoadError` live in `src/components/` because several features use them.

## Web: admin review (DIK-006)

- `decideRoute` returns `admin` for role `admin`; the home page sends admins to `/admin/verifications` and `/verification` sends them on to `/`.
- The proxy relays a file only for `admin/verifications/<id>/document/` (ok reply, PDF/JPEG/PNG only, `Cache-Control: private, no-store`); per-endpoint allowed query parameters live in `proxy-path.ts` (`allowedQuery`).
- `Dialog` moved to `src/components/` (also used by the reject dialog). Tab filtering is `src/components/admin/tabs.ts`.

## Flutter: launcher icons (DIK-008)

- Art and how to redraw it: `dikonekti/assets/icon/README.md`. Platform icon files are generated by `dart run flutter_launcher_icons` (config in `dikonekti/pubspec.yaml`) and committed; never edit them by hand.
- Flutter is not on the PATH on the dev machine; the SDK lives in `~/flutter`, pinned to **3.41.9 (Dart 3.11.5)**, the line this project's lock and Gradle 8.14 / AGP 8.11.1 were made with (Flutter 3.50 needs Gradle 9.3.1). Use `~/flutter/bin/flutter`. Its JDK is set to the system JDK 21 (`flutter config --jdk-dir`): Android Studio's bundled Java 25 is rejected by Gradle 8.14. The first Android build downloads two NDKs (about 2.3 GB each) and is slow. The nested folder `dikonekti/dikonekti` is a stale duplicate (DIK-009): never edit or run commands inside it.

## Running the backend

`Dikonekt_Backend/dikonekti/README.md` explains how to run and test it. The server needs `DJANGO_SECRET_KEY`, `DJANGO_DB_NAME`, `DJANGO_DB_USER` and `DJANGO_DB_PASSWORD` in the environment (and `DJANGO_ALLOWED_HOSTS` and `DJANGO_MEDIA_ROOT` unless `DJANGO_DEBUG=true`); without them it stops at start-up and names the missing one. Copy `.env.example` and load it with `set -a; . ./.env; set +a`.
