# DIK-008: Dikonekti launcher icon in the Flutter app

**Type:** Chore
**Priority:** Low
**Platform:** Flutter app (`dikonekti/`)
**Depends on:** None

---

## Problem Statement

The Flutter app still uses the default Flutter logo as its launcher icon on Android, iOS, the web build and the desktop builds. The web dashboard and the app's own login screen already show the Dikonekti mark (a white hand-and-heart on a purple gradient circle), so the app looks unfinished and is hard to find on a phone home screen. This affects every Doctor and Disabled User who installs the app.

---

## User Stories

- As a **Disabled User**, I want the app on my phone to show the Dikonekti logo, so that I can recognise and open it quickly in an emergency.
- As a **Doctor**, I want the same logo on the app and the web page, so that I know they belong together.

---

## Approved Design / Behaviour

The launcher icon is the Dikonekti mark: the white Material `volunteer_activism` glyph on the app's purple (`#6750A4` to `#9B7FE8`), exactly as on the login screen and the web favicon.

| Platform | Icon |
|---|---|
| Android | Adaptive icon: solid `#6750A4` background layer and a white glyph foreground layer kept inside the safe zone, plus the legacy round and square icons for older devices |
| iOS | Square, full-bleed gradient with the glyph, no transparency (iOS rounds the corners) |
| Web | Favicon and the 192 px and 512 px icons, and the maskable versions, in `web/icons/` |
| Windows, macOS | App icon generated from the same artwork |

- One source artwork (a 1024 px PNG and a foreground-only PNG) is committed under `assets/icon/`, generated from the existing web icon (`dikonekti-web/src/app/icon.svg`) so the three places never drift.
- The icons are generated by the `flutter_launcher_icons` tool from a configuration in `pubspec.yaml`, and the generated files are committed.
- The web app manifest uses the name "Dikonekti" and the brand colour for its theme.

### Key Implementation Notes
- Render the PNGs once from the SVG with a command-line tool (for example `rsvg-convert` or ImageMagick) and commit them, so that building the app never needs that tool.
- Android adaptive icons crop the outer third of the canvas, so the glyph must sit within the central safe zone. Check the result in the adaptive icon preview, not only the square image.
- iOS rejects icons with an alpha channel, so the 1024 px iOS source is flattened onto the gradient.
- The tool overwrites existing icon files and, on some versions, edits the Android manifest and `Contents.json`. Review the diff and keep unrelated changes out.
- Rejected alternative: hand-copying icon files at every size. It works, but nobody can regenerate them when the logo changes.
