# DIK-001: Doctor home dashboard on web (Next.js)

## Summary
Create `dikonekti-web/`, a Next.js (App Router, TypeScript, Tailwind) app whose only authenticated screen is the Doctor home dashboard. It mirrors the Flutter `DoctorDashboard` (welcome header, emergency alerts, patients, quick actions) in a two-column desktop layout. Django is untouched. Auth runs through a Next.js server layer (BFF): login and refresh happen in route handlers, JWTs live in `httpOnly` cookies, and the browser only calls same-origin `/api/*` routes that proxy to Django with the bearer token. Key trade-off: a proxy layer (more code) in exchange for tokens JavaScript can never read.

## Architecture Conformance
No project rule files exist (`.ai/rules.md` absent). Applying Next.js App Router conventions:
- Secrets and Django URL stay server-side: `API_BASE_URL` is not `NEXT_PUBLIC_`; `config.ts` and `session.ts` import `server-only` so a client import fails the build.
- Wire types live in `lib/types.ts` and mirror the Django JSON exactly (snake_case fields mapped once, in the API client), not scattered across components.
- One component per file; presentation components receive data via props, only `Dashboard.tsx` and the dialogs fetch.
- Business-ish logic (time-ago, greeting, maps URL, path allowlist) is pure and lives in `lib/`, unit-tested, never inline in JSX.
- Role authorization stays on the server (Django `IsDoctor`, `IsOwningDoctor`). The web role gate is UX, not security.
- New top-level directory name: `dikonekti-web/`. It cannot be `dikonekti/web/` (Flutter's). Recorded in `.ai/context.md` in this PR.
- Boy-scout: none; no existing files are touched except the ticket doc.

## Implementation Steps
1. Scaffold: in repo root run `npx create-next-app@latest dikonekti-web --ts --tailwind --eslint --app --src-dir --use-npm --import-alias "@/*"`. Delete boilerplate page content and assets.
2. Add deps: `swr`, `server-only`; dev deps: `vitest`, `@vitejs/plugin-react`, `jsdom`, `@testing-library/react`, `@testing-library/jest-dom`, `@testing-library/user-event`. Add `vitest.config.ts`, `vitest.setup.ts`, npm scripts `test`, `typecheck`.
3. `src/lib/types.ts`: types for profile (`username, role, display_name, first_name, middle_name, last_name, email, phone_number, area, disability_type, specialization`), alert (11 fields from `EmergencyAlertSerializer`), appointment (`id, patient_username, patient_name, requested_time, reason, status, created_at`), message (`id, sender_username, recipient_username, body, timestamp, read`).
4. `src/lib/proxy-path.ts`: `resolveProxyPath(segments: string[], method: string): string | null`. Allows only `me/`, `alerts/`, `alerts/<int>/acknowledge/`, `patients/`, `appointments/`, `appointments/<int>/status/`, `messages/` with the right methods (`GET`; `PATCH` for acknowledge and status; `POST` for `messages/`). Rejects `auth/*`, `..`, empty segments, non-numeric ids, encoded slashes, wrong methods. Returns the normalized Django path with trailing slash, else `null`.
5. `src/lib/config.ts`: `getApiBaseUrl()` reads `process.env.API_BASE_URL`, trims trailing `/`, throws a clear error if unset or not http(s).
6. `src/lib/session.ts`: constants `ACCESS_COOKIE='dik_access'`, `REFRESH_COOKIE='dik_refresh'`. `cookieOptions(maxAgeSeconds)` returns `httpOnly, sameSite:'lax', path:'/', secure: NODE_ENV==='production', maxAge`. `applySessionCookies(response, {access, refresh?})` (access 12h, refresh 30d to match `SIMPLE_JWT`), `clearSessionCookies(response)`, `refreshTokens(refresh): Promise<{access, refresh?} | null>` (POST `auth/refresh/`, returns `null` on any non-200 or network error).
7. `src/lib/format.ts`: pure helpers ported from Flutter (`timeAgo` matches `_timeAgo`: Just now / Nm ago / Nh ago / Nd ago; greeting thresholds <12, <18; `mapsUrl`, `coordinatesLabel` to 5 decimals or "Location unavailable"; `telHref` trims and returns `null` for blank; `formatDateTime`). All take an injectable `now`.
8. `src/lib/health-tips.ts`: export the four doctor tips verbatim from `_healthTipsFor(isDoctor: true)`.
9. `src/lib/api-client.ts`: `apiFetch<T>(path, init)` calling same-origin `/api/<path>`. Non-2xx throws `ApiError(status, message)`; message extraction handles DRF shapes (`detail`, `{field:[msgs]}`, `non_field_errors`, plain string) with a generic fallback. 401 triggers `window.location.assign('/login')`.
10. `src/app/api/auth/login/route.ts` (POST `{username,password}`): call Django `auth/login/`. On 200 set both cookies and return `{role, display_name}` only (never tokens). On 400/401 forward `{message}` with the same status. On network failure return 502 `{message}`.
11. `src/app/api/auth/logout/route.ts` (POST): clear both cookies, 204.
12. `src/app/api/[...path]/route.ts` (GET, POST, PATCH): resolve path via `resolveProxyPath` (404 if `null`), read access cookie (401 if absent and no refresh cookie), forward body/query (`?patient=` only for `messages/`), attach `Authorization: Bearer`. On a 401 from Django: `refreshTokens` once, retry once with the new access token and set the new cookies on the response; if refresh fails, clear cookies and return 401. Pass through status and JSON body. Never forward `cookie` or client `authorization` headers.
13. `src/proxy.ts` (exports `proxy`; `middleware.ts` is deprecated in Next 16): matcher excludes `_next`, static files and `/api`. Without access cookie but with refresh cookie: call `refreshTokens`; on success continue with new cookies set on request and response; on failure clear cookies. Without a usable session on any route except `/login`: redirect to `/login`. With a session on `/login`: redirect to `/`.
14. `src/app/layout.tsx` and `globals.css`: theme tokens from the Flutter doctor palette (`#1D3557`, `#457B9D`, `#C1121F`, `#2A9D8F`, `#14213D`, page bg `#F3F7F6`), light only, system font stack.
15. `src/app/login/LoginForm.tsx` (client) and `page.tsx`: username, password, submit, loading, inline error (`role="alert"`), then `router.replace('/')`.
16. `src/app/page.tsx` (server): fetch `/me/` with the access cookie via a server helper. 401 or fetch failure: redirect to `/login`. `role !== 'doctor'`: redirect to `/unsupported`. Otherwise render `<Dashboard profile={...} />`.
17. `src/app/unsupported/page.tsx`: message "The web dashboard is for doctors. Please use the Dikonekti mobile app." plus `LogoutButton`.
18. `LogoutButton.tsx`: POST `/api/auth/logout`, then `router.replace('/login')`.
19. `useDashboardData.ts`: `useAlerts()` and `usePatients()` via SWR, `refreshInterval: 12000`, `refreshWhenHidden: false`, `revalidateOnFocus: true`, keep previous data on error. `acknowledge(id)` PATCHes `alerts/<id>/acknowledge/` then mutates the cache with the returned alert.
20. `Dashboard.tsx`: greeting + `WelcomeHeader`; two-column grid at `lg` (alerts left; patients and quick actions right), single column below. Splits active vs resolved. Shows `ErrorBanner` on error without hiding data, "no alerts" and "no patients" empty states, loading skeleton on first load only.
21. `WelcomeHeader.tsx`, `AlertCard.tsx` (red or teal left border, name, "Needs urgent help · time" or "Marked resolved · time", disability and area, call chip via `telHref`, Acknowledge button on active only, per-card pending and error state), `AlertLocation.tsx` (coordinates, Open in Google Maps in a new tab with `rel="noopener noreferrer"`, Copy coordinates with "Copied" feedback, or "Location unavailable" plus `location_error`), `PatientCard.tsx` (initial avatar, full name, disability and area, call button).
22. `TabTitle.tsx`: sets `document.title` to `(N) Dikonekti` when N > 0, else `Dikonekti`; restores on unmount.
23. `QuickActions.tsx`: Profile, Health Tips, Schedule, Messages buttons with a single `openDialog` state.
24. `Dialog.tsx`: wrapper on native `<dialog>` (`showModal`, Escape closes, focus return, labelled title, close button). `ProfileDialog.tsx` (rows as in Flutter doctor profile), `HealthTipsDialog.tsx`.
25. `ScheduleDialog.tsx`: `GET appointments/`; list sorted as returned; status chip (pending, confirmed, declined); pending rows get Confirm and Decline via `PATCH appointments/<id>/status/ {status}`; load, empty, error states; per-row error.
26. `MessagesDialog.tsx`: patient picker from `usePatients()` data; thread via `GET messages/?patient=<username>` (poll every 12s while open); bubbles aligned by sender; composer posts `{body, recipient_username}`; blank body disabled; load, empty and error states.
27. `.env.example`, `README.md` (env, `npm run dev|test|build|lint`, how to run Django locally), root `.ai/context.md` module map.
28. Update the ticket doc: Approved Design bullet "No tokens are kept…" becomes "Tokens are set for any valid login so logout works; dashboard routes and data requests are gated on the profile `role`." Add a Scope note.

## Acceptance Criteria
- [ ] Doctor logs in at `/login` with valid credentials and lands on `/` showing alerts and patients from the API, with no browser console errors.
- [ ] Invalid credentials show the server's error message and keep the Doctor on `/login`.
- [ ] Unauthenticated visitor to `/` is redirected to `/login`.
- [ ] Refreshing the page keeps the Doctor logged in. Logout clears the session and returns to `/login`.
- [ ] Access token expiry (401) is handled by a silent refresh via the refresh token. If the refresh fails, the Doctor is sent to `/login`.
- [ ] Auth tokens are never readable from page JavaScript (`document.cookie` and web storage show no token).
- [ ] At >= 1024px the Doctor sees two columns (alerts left; patients and quick actions right). Below that the layout is a single column with no horizontal scroll at 360px width.
- [ ] A new unacknowledged alert from a patient appears within 12s without a reload, and the tab title count updates.
- [ ] Doctor can acknowledge an alert of their own patient. It moves to Resolved. A failure shows an error message and leaves the alert active.
- [ ] Doctor can open the map link, copy coordinates, and sees "Location unavailable" plus the error when GPS is missing.
- [ ] Doctor sees the empty states ("no alerts", "no patients") and an error banner when the API fails.
- [ ] Doctor can open Profile and Health Tips, accept or decline an appointment request, and send a message to a patient.
- [ ] Disabled User login on web shows the "use the mobile app" page and a working logout. The dashboard data endpoints are never requested for them.
- [ ] Doctor sees only their own patients' alerts and patients (server-enforced). No other doctor's data renders.
- [ ] `npm run build`, `npm run lint` and type-check pass. Backend base URL is set only via `API_BASE_URL` in the environment, with no hardcoded host.

## Risks & Gotchas
- The ticket says "no tokens are kept" for Disabled Users, but its AC also requires a working logout. Resolved by keeping cookies for any valid login, gating on `role` in `page.tsx`, and updating the ticket doc (step 28).
- `ROTATE_REFRESH_TOKENS=True`: every refresh returns a new refresh token that must replace the cookie. `BLACKLIST_AFTER_ROTATION` is not set, so two concurrent refreshes will both succeed.
- Next.js proxy (formerly middleware) cannot call `cookies().set` on the incoming request; set cookies on both the forwarded request headers and the `NextResponse` so the same request already sees the new access token.
- Middleware decides session presence by cookie existence only, not by JWT validity. Django remains the authority; a bad token leads to a proxy 401 → redirect to `/login`.
- `refreshTokens` failure must clear cookies to avoid redirect loops between `/` and `/login`.
- `lat/lng = 0` is valid; use `!= null` checks, never truthiness.
- Proxy allowlist is the main SSRF and traversal defense; never build the upstream URL by concatenating unvalidated segments.
- `timeAgo` and greeting use the client clock; hydration mismatch risk if rendered on the server. Render time-relative text only in client components, or `suppressHydrationWarning` on those nodes.
- Polling pauses when hidden (`refreshWhenHidden: false`) so a background tab will not update the title until focus returns. Accepted trade-off.
- Reuse check: closest existing screen is Flutter `DoctorDashboard`. Copied: gradient welcome header (`#1D3557`→`#457B9D`), alert card left border 5px red/teal, pill count badges, card radius 14-16, white cards with `#E7ECEF` border, section order and copy.
